# Ids on list steps (2026-10-01)

Agreed with the user on 2026-10-01 ("add syntax for the player to add discriminating id strings. Two bots commanded to
build the same thing, with the same discriminating id, at the same time have only one build and the one that arrives
late assists"; "Agreed, look into the taken-as-done bug first, then build it"). The player's lists are its own order,
carried out by code: nothing here is asked of Jev and nothing is decided about the game.

## Why

player-33-hard, 11:58: "Starting the Advanced Vehicle Plant at avp_yard (south of home) with three constructors on it".
Each of the three lists carried the step; two frames began a second apart (12:17, 12:18: neither frame stood when the
other builder arrived, so the 900-elmo "a frame of that type already started" help did not see it), and the player had
one taken apart at 17:37. A list had no way to say "this is the same building". The same lack sits under the list
problems of the day: a list sent again cannot say which of its steps are already done, so the bot guessed (the
first-list skip, retired; "taken as done" by type alone, fixed).

## The law

Steps carrying the same id are one building: the first builder to reach the step starts it, any other builder reaching
a step with that id helps build it while it is unfinished, and the step is done once the building stands.

## Syntax

A step's last word, beginning with `#`: `armavp avp_yard #avp1`, `armsolar #s3`, `extractor spot_5 #e5`. Letters,
digits and underscores, 24 at most. Optional: a step without one is its own building, as before. On `assist` and
`stop` the tool refuses it.

## What a step with an id finds (`Pianist::tag_state`)

| the id | the step |
|---|---|
| unknown, or its building is gone, or the builder that claimed it is dead or off that build | this builder starts it and holds the claim until the engine makes the frame |
| claimed by another builder still on its way | this builder helps that builder (a guard order: it assists what the other builds) |
| its frame stands unfinished | this builder helps build the frame (a repair order) |
| this builder's own build | the build under way: done |
| its building stands | done |
| another type's building | skipped and said: an id is one building |

A helper takes no list step until the building stands or is gone; then its guard or repair is ended and its list goes
on (or the pass has it back, when the list is over). A helper the pass sends elsewhere gets the step back on its list.
At most one live building per id: one destroyed frees its id, and a step with it builds again.

## The tool

- The same id on two different steps in one call is refused ("an id is one building, written the same on every list").
- The same factory step on two builders' lists without an id is answered with a note that this is two factories and
  how to write one. A note, not a refusal: two factories may be meant.
- The `plan` tool reads steps without their ids.

## Not done

- Ids across calls are checked when the step is played, not by the tool (the tool does not hold the bot's table).
- The 900-elmo help of an untagged factory frame of the same type (H-HANDS-STARTED across builders) stays for lists
  without ids; a tagged step that lands on it adopts that frame as its building.
